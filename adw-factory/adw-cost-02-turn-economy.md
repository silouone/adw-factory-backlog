# P2 — turns are the multiplier: cap them, fill them, and price the gear

> **Evidence:** `ai_docs/2026-09-21-token-audit-FULL.md` §1, §5.
> **Modelled saving: ~526M (17.3%) from R1 alone**, plus an unmeasured but
> potentially larger amount from R3.
> **Depends on `adw-cost-01` deliberately** — that ticket lowers the curve
> this one splits. Landing them in the other order re-measures a baseline
> that is about to change.

## The cost model

`cost ≈ Σ over turns of (context at that turn)`. Measured: **12,557 turns**,
**243K average context per turn**.

Fitted across all 50 `build`/`test` instances by log-log least squares:

```
cacheRead = 113,491 × turns^1.19     (n=50)
```

> **The exponent is 1.19, not 2.1.** An earlier two-point estimate through an
> outlier said otherwise and was wrong. Superlinear, so splitting sessions
> genuinely pays — but it is a **17%** lever, not a collapse. Build to the
> fitted number; do not re-derive the optimistic one.

Concentration: the **top 10 of 50** `build`+`test` instances are **1.183B of
2.248B = 52.6%** of that family's burn. One-fifth of sessions, half the cost,
and they are the long ones.

## Requirements

- [ ] **R1 — cap a node's turns and resume in a fresh session.** At the cap
      the agent writes a compact state artifact (files touched, decisions
      made, the open thread) and a **new** session continues from that
      artifact rather than the transcript. Fitted saving at a 100-turn cap:
      **526M = 17.3%**.
- [ ] **R1a — the cap is per-stage and per-target overridable**, defaulting
      to a factory constant. `plan` does not need the same ceiling as `build`.
- [ ] **R1b — a resumed node is one node in the journal.** The run screen and
      `run-autopsy.ts` must not report a capped-and-resumed `build` as two
      builds; the round counter lives in the engine (S2.3) and this must not
      grow a second one beside it.
- [ ] **R2 — a turn must not carry a single independent tool call.** When the
      agent issues one read/grep that had no dependency on an in-flight
      result, the hook rejects the turn and tells it to batch. Turn count is
      the multiplier; this cuts turns at constant work.

  > **The audit's ★ pick.** Independently generated by four of the five
  > ideation frames. It changes no node's logic — it is a hook.

- [ ] **R2a — never block a genuinely dependent call.** A read whose path
      came from the previous result is legitimate and must pass. If that
      cannot be decided reliably, R2 ships as a **warn-and-journal** counter
      first and the denial lands only once the false-positive rate is
      measured. Do not trade correctness for tokens.
- [ ] **R3 — price the gear that has never been used.** All **175 of 175**
      usage records read `sonnet` / `effort:high` / `profile:standard`.
      `profiles.ts` defines `swift` (sonnet/medium) and `cheap` (haiku/low);
      **neither has ever been selected**, and `adw-profile-03` shipped `swift`
      as PR #81 without it ever running.

  > **Why this belongs to a turn ticket, not a model ticket.** Output tokens
  > are 0.28% of the bill, so effort looks irrelevant — but **every output
  > token becomes context for the rest of its session and is re-read on every
  > later turn**. Modelled at half the remaining session, the re-read cost of
  > the model's own thinking is **≈482M = 15.8% of the bill**. Effort is a
  > turn-economy lever, not a rounding error.
  >
  > The open question is whether `medium` needs *more* turns to reach the same
  > result, which would net out worse. **There is no A/B because `swift` has
  > never run.**

- [ ] **R3a — run the A/B, don't assume it.** Dispatch one real ticket twice,
      `standard` vs `swift`, and report **turns, total tokens and outcome**
      for both. The deliverable of R3 is the measurement plus a recommended
      default — not a config change made on faith.
